Probe 结构

本次实现不是 pooled paragraph classifier，而是 token-level weak supervision probe。每个 token hidden state 经过一个共享结构，输出正向 value evidence 与反向/opposite evidence。

token_hidden[layer] -> LayerNorm -> Linear(hidden, 4)  # positive head
                    -> LayerNorm -> Linear(hidden, 4)  # negative head

token logits -> masked logmeanexp -> paragraph logits -> BCE loss
逐 token 含义：训练监督来自段落级 relation，但模型保留每个 token 的 value score。因此 token 分数应解释为 weakly-supervised relevance attribution，而不是人工 token 标签的真值。

结论

  • Probe 对明确约束稳定，例如“别排队太久”“安静点，一个人”“不要太折腾”能激活合理 value 或 opposite value。
  • Probe 对短、弱、隐含表达偏保守。19/40 条没有任何 positive value 过 0.5，但很多 top-1 方向仍与 LLM 预期一致。
  • 舒适安全 是最容易被模糊输入激活的 value；它覆盖“安静、不累、放松、不要太吵”等本地生活高频表达。
  • 健康克制 对“累/身体状态/别太辣”有过激活倾向，后续需要用 hard negative 把身体舒适和饮食健康拆开。
  • 社交连接、家庭照护、新奇探索 在弱表达上分数偏低；当前 probe 更像“强证据检测器”，不是弱意图召回器。

后续建议

  • 新增 weak_related 或 implicit_related 标注层级，不要把模糊表达直接塞进普通 related，否则会损伤强证据边界。
  • 线上可采用双阈值：>=0.5 作为强激活，0.25-0.5 作为候选提示，由 intent/parser 或 memory 再确认。
  • 为 健康克制 vs 舒适安全、氛围仪式 vs 体验享受、社交连接 weak positive 构造 targeted hard negatives。
  • 评估时保留 LLM 生成的 likely_values 只作参考，不作为金标；正式结论需要人工复核或多模型一致性标注。

限制与下一步

  • 当前 token-level 输出是弱监督 attribution，训练标签仍来自段落级 related/opposite/unrelated，不能等同于人工 token relevance 标注。
  • 测试集每个 value/relation 只有 10 条，AUC/F1 很高说明信号明显，但仍需要人工真实请求集验证泛化。
  • 合成数据中可能存在边界样本和标签噪声，例如约会、家庭、健康、便利之间会有交叉。
  • 后续建议补 200-400 条人工 token relevance 标注，用于校准 token evidence，而不是只看段落分类。
