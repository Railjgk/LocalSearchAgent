优化版：先用规则 Probe 跑通当前价值信号，再接闭源与训练模型

推荐把第一版收敛为“现有规则 intent parser + current-turn value probe + current-first memory merge”。 先证明当前轮价值信号能稳定进入 `constraints.score_weights`，并且不会被长期 memory 覆盖； 闭源解析、embedding regressor 和 activation probe 放到链路稳定后的增强阶段。

MVP 收窄 第一版只做规则 probe 与可审计合并，不引入新模型依赖。
双通道 现有 parser 负责结构化意图，probe 独立输出价值分数。
当前优先 显式 intent 与当前 probe 优先，memory 只补缺口。
不改主干 只增强 `intent_parser -> memory_manager`，保持图结构稳定。

推荐结论

第一版不新增图节点，直接让 `intent_parser_node` 在现有规则解析之后调用 `probe_current_turn_values`。 `memory_manager_node` 负责把当前 probe 与历史 `value_profile` 做缺口补充，输出后续模块统一读取的 `effective_value_weights`、`score_weights` 和合并审计。

rule intent parser rule value probe current-first merge traceable score weights

优先级规则

current explicit intent
  > current value probe
  > recent memory
  > long-term memory
  > defaults

这条规则是方案的产品边界：memory 的作用是个性化补全，不是替用户当前输入做主。

优化后的范围控制： Phase 1 不接闭源 intent parse，不训练 embedding probe，不写长期画像；只新增当前轮 value payload、 合并策略和测试。闭源 API 与训练版 probe 作为 Phase 4 之后的可插拔 provider。

架构

现有工作流是 `intent_parser -> memory_manager -> scenario_planner`。优化版保持主链路稳定： `intent_parser_node` 继续产出结构化 intent，并额外产出当前轮 `value_probe`； `memory_manager_node` 再执行 current-first 合并和投影。

边界声明： MVP 阶段是规则/文本 probe。后续即使接入闭源 API，也只能称为 external text/embedding probe； 只有真正读取开源模型内部 activations 时，才升级为 BACH-V 意义上的 activation probe。

Probe 设计

Probe 与 intent parse 解耦，避免把 value 判断混进同一个 prompt JSON。优化后的第一版只做规则与 evidence span， 让链路、schema、merge trace 和下游评分先稳定；训练版和闭源/embedding provider 在后续阶段以可选模块接入。

输入

  • raw_user_input
  • normalized_text
  • 可选：现有 parser 产出的 intent

模型

  • Phase 1：规则 + keyword/evidence span
  • Phase 4：embedding + multi-label regressor
  • Future：开源模型 activation probe

输出

  • 每个 value 的 score
  • confidence 与 evidence
  • missing_value_ids 与 conflicts

推理流程

def probe_current_turn_values(raw_text, intent=None):
    rule_hits = rule_probe(raw_text)
    model_scores = model_probe(raw_text, intent) if model_enabled() else []
    merged_scores = calibrate_and_merge(rule_hits, model_scores)
    evidence = extract_evidence_spans(raw_text, merged_scores)
    return build_value_probe_payload(merged_scores, evidence)
命名建议： 对外可以叫 `Intent Value Probe` 或 `Current-Turn Value Probing`。MVP 文档和代码注释都应避免 hidden-state、 steering、activation 等表述，直到实现真的读取模型内部激活。

Memory 合并策略

Memory 的角色是补充当前未体现的用户画像，而不是覆盖当前输入。合并后输出统一上下文给后续 planner/ranker 使用； 当前轮 `value_probe` 默认不直接写入长期 `value_profile`，是否沉淀由 memory ingestion 另行根据重复证据、TTL 与用户反馈判断。

当前输入明确体现 value

使用 current probe 为主，memory 只增强置信度或补充 evidence。

→
当前输入未体现 value

memory 可按 TTL 与 confidence 衰减补充，补充权重不得高于当前轮信号。

推荐公式

if current_confidence >= 0.70:
    effective_score = current_probe_score
    source = "current_probe"
elif current_probe_score > 0:
    effective_score = (
        0.65 * current_probe_score
        + 0.25 * recent_memory_score
        + 0.10 * long_term_score
    )
    source = "current_probe_with_memory_support"
else:
    effective_score = memory_score * memory_confidence * supplement_weight
    source = "memory_supplement"

effective_score = min(effective_score, current_probe_score or 0.45)
来源 补充权重 说明
current_probe 1.00 当前轮价值信号，直接参与本轮决策。
short_term 0.45 近期对话或最近反馈，适合补充临时状态，如“最近在减脂”。
long_term 0.30 稳定偏好，适合补充常见家庭/便利/预算倾向。
stable_profile 0.25 画像默认项，只在当前完全缺失时弱补充。

冲突处理

if current says "今天想吃火锅" and memory says "health=high":
    keep current food intent
    mark conflict: health_memory_not_applied
    do not update long-term health downward
    optionally add soft health hint: "可选清淡锅底/少油"
后续模块只读合并结果： `scenario_planner`、`candidate_generator`、`constraint_filter`、`plan_optimizer` 不直接读取原始 memory value，而读取 `constraints.effective_value_weights`、`constraints.score_weights`、`constraints.value_sources` 和 `value_merge_trace`。

训练与评估

训练版是链路稳定后的增强项，不进入 MVP 阻塞路径。后续可参照 BACH-V 的抽象到具体框架， 但把任务改写为本地生活 value detection。BACH-V 原始方法使用开源模型 MLP activation、0-6 token relevance 和线性 probe； 本项目先复用其数据构造和验证思想，待规则版有 ablation 证据后再训练模型。

A-A 抽象价值

价值定义、边界、同义表达、反义表达。

"convenience means reducing friction,
uncertainty, queueing and travel cost."

A-C 具体请求

用户自然语言需求，标注 value 强度和 evidence。

"孩子小，附近玩一下，别太折腾"

C-C 决策理由

方案选择、拒绝理由、反馈修改。

"没选热门商圈，因为排队久且孩子累"

标注格式

{
  "text": "周末带老婆孩子吃点健康的，别太折腾",
  "labels": {
    "family_care": 6,
    "health": 5,
    "convenience": 4,
    "cost_sensitivity": 0
  },
  "evidence": {
    "family_care": ["老婆孩子"],
    "health": ["健康的"],
    "convenience": ["别太折腾"]
  },
  "split": "train"
}
评估项 目标 通过标准
Pearson / Spearman 验证分数回归与标注一致 核心 value 维度稳定为正，训练版优于规则版
Macro F1 / AUC 验证多标签 value 是否命中 各维度无明显塌缩，低频 value 单独报告
Evidence span hit rate 验证输出是否能解释 value 来源 核心场景样本 evidence 覆盖率高于规则 baseline
Diagonal dominance 借鉴 BACH-V 验证 probe specificity matched value corpus 分数高于 mismatched corpus
Downstream ablation 验证 probe 对方案质量有用 `intent only`、`intent + probe`、`intent + probe + memory` 有可解释差异

优化实施计划

实施目标不是一次性做完整研究系统，而是先把当前轮价值信号作为稳定、可解释、可测试的 A-stage 输出接进现有链路。 下面四个阶段按“可运行链路 → 合并投影 → 验收演示 → 模型增强”递进。

Phase 1：规则 Probe 接入 新增 schema 与 rules，`intent_parser_node` 返回 `value_probe`，不接闭源 API。
Phase 2：Current-first Merge 拆分 value merge 与 score projection，输出 trace、sources、effective profile。
Phase 3：测试与 Demo 覆盖 current 优先、memory 补缺、冲突记录和下游只读合并结果。
Phase 4：可选模型增强 在规则版通过后，再接 embedding regressor、闭源 parse provider 和 ablation。

执行顺序

步骤 改动重点 完成标准
1. 定义 value contract 新增 `ValueProbeItem`、`ValueProbeResult`、MVP taxonomy 与 evidence span 约束。 空输入、无命中、多 value 命中都返回稳定 JSON shape。
2. 实现规则 probe 覆盖 `family_care`、`health`、`convenience`、`cost_sensitivity` 四个 MVP value。 “老婆减脂”“孩子5岁”“别折腾”“人均200”等样例能给出分数和证据。
3. 接入 parser node `intent_parser_node` 在现有 `parse_intent` 后调用 probe，不改变原 intent/constraints 合约。 旧测试继续通过，新测试能读取 `state["value_probe"]`。
4. 拆分 memory policy 把 value 合并与 score projection 拆成独立函数，保留 `apply_value_memory` 兼容入口。 `constraints.effective_value_weights`、`value_sources`、`score_weights` 同时存在。
5. 输出审计 `memory_manager_node` 输出 `effective_value_profile` 与 `value_merge_trace`。 每个 value 都能解释来自 current probe、memory supplement 或 conflict skip。
6. 做 ablation demo 固定输入，对比 only intent、intent + probe、intent + probe + memory。 方案差异能被 `score_weights` 与 trace 解释，而不是只靠主观描述。

暂缓项

暂缓内容 原因 重新启动条件
闭源 intent parse provider 当前 repo 已有规则 parser，先避免 API、prompt drift 和 schema 校验风险。 规则链路 demo 稳定，且需要覆盖规则难解析输入。
embedding regressor 没有标注集前容易不如规则 baseline，且会拖慢 MVP 验收。 收集到 A-C/C-C 标注样本，并有规则 baseline 指标。
activation probe 需要开源模型激活访问，和当前闭源/API 路径不是同一实现层级。 明确使用可访问 activation 的开源模型，并单独设计实验。
把 current probe 写入长期画像 单轮表达可能是临时状态，直接写长期 profile 会污染 memory。 由 memory ingestion 根据重复证据、TTL 和用户反馈单独决策。

最小测试集

  • `intent_parser` 能在同一输入下同时返回 `intent`、`constraints`、`value_probe`。
  • 当前输入含 “老婆在减脂” 时，`health` 来自 current probe，而不是 memory。
  • 当前输入不含 “别折腾” 但历史有 `convenience` 时，仅以补充权重进入 `effective_value_weights`。
  • 当前输入与 memory 冲突时，当前输入优先，`value_merge_trace` 记录未应用原因。
  • 后续 planner 只读取合并后的 `constraints.score_weights`，不直接依赖原始 memory value。

风险

风险 影响 缓解
外部 probe 被误解成 hidden-state probing 研究叙事被质疑 MVP 明确称为 rule/text probe；闭源 API 阶段称为 external text/embedding probe；activation probe 只作为未来增强。
Memory 过度补充，压过当前输入 用户觉得系统不听话 强制 current-first merge，历史补充权重不超过 0.45，并记录 trace。
Value 标签太虚 评估与演示不清晰 每个 value 必须输出 evidence span，训练集包含边界样本和冲突样本。
Probe 与 intent parse 不一致 下游约束混乱 冲突进入 `conflicts`，由 memory merge 统一仲裁；显式 intent 优先。
训练样本不足 模型不如规则 baseline 先用规则 fallback 发布，逐步增加 A-C 与 C-C 数据，并做 ablation。
非目标： 第一阶段不替换现有 intent parser，不做闭源模型 activation steering，不训练 embedding regressor， 不让 memory 覆盖当前明确请求，不把 value probe 结果直接写死为长期画像。

依据

  • BACH-V 提出 A-A、A-C、C-C 三层价值理解框架，并用 value-specific probe 验证抽象价值到具体事件和决策的迁移： arXiv:2601.14007。
  • BACH-V 的原始 probing 方法基于开源模型 MLP output activations、0-6 token relevance、线性 probe 和 L1 正则； 本项目 MVP 阶段只复用数据构造和评估思想，不声称 hidden-state probing。
  • 当前仓库已有 `value_profile`、`score_weights`、多目标 optimizer 的基础，适合先做 current-turn value probing 与 memory supplement。

本文档是优化后的实现方案，不包含代码改动。后续实现建议按 Phase 1 到 Phase 4 逐步提交， 每阶段补充对应测试与运行报告；闭源和训练模块在规则链路验收后再接入。
