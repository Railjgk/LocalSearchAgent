一页摘要

职责

在 Intent Parser 后读取用户记忆，按当前输入优先策略投影约束，检索相关证据，写入本轮信息，并输出可审计 trace。

检索

使用 deterministic sparse、v2 graph expansion、可选 BaseStore semantic search 融合，最后按安全规则、相关性、置信度排序。

写入

每轮写入 episode，遇到孩子年龄写 long-term companion，遇到伴侣低卡写 short-term companion，并做 duplicate refresh。

边界

朋友场景不会召回孩子、伴侣、健康饮食这类家庭专属记忆；短期事实通过 ttl_turns 衰减。

维护判断： 改 memory 行为时优先看 src/memory/policy.py、src/memory/retrieval.py、 src/memory/ingestion.py 三处。src/nodes/memory_manager.py 只做薄编排。 Intent Parser 只负责理解当前话语；Memory 负责保存和召回跨轮可复用事实。

模型接口判断

2026-05-18 检查结论： 基于当前验证，A-stage memory 暂时不需要额外改代码来预留真实模型接口。现有实现已经保留了足够的轻量扩展点， 继续保持 deterministic baseline 更有利于离线 demo、回归测试和后续 B/C 兼容。

为什么现在不接模型

  • intent_parser_node 已经通过 build_intent_prompt 保留 prompt 包装层，未来可替换 parse_intent 内部实现。
  • 当前规则解析已覆盖 family、friends、couple、low_budget、时间、地点、预算、同行人、饮食状态、距离偏好和活动偏好。
  • memory_manager_node 已经把 value memory 投影为 value_weights、value_confidence 和 score_weights，满足粗粒度 value 关联目标。
  • 检索层已有 sparse、graph 和可选 LangGraph BaseStore semantic adapter；semantic search 失败会自动回退 sparse。
  • 现在引入真实模型会增加环境变量、网络、成本和非确定性测试风险，收益暂时低于维护成本。

什么时候再接模型

  • 用户表达明显超出规则覆盖范围，规则维护成本开始上升。
  • 需要开放领域抽取更多实体、关系、偏好和长期 value。
  • 需要由模型生成 value 的 score、confidence、evidence，而不是当前粗粒度规则/画像投影。
  • 已经准备好 JSON schema 校验、失败回退、离线测试夹具和稳定观测字段。

后续接入模型时保持外部契约不变：模型只替换 parse_intent 的内部实现，输出仍必须满足当前 intent 和 constraints_from_intent 合约；value 生成也应先落到 value_profile 或 Memory Atom，再由 apply_value_memory 投影到 planner constraints。

A-stage 在做什么：Intent Parser 与 Memory 的边界

A-stage 的目标不是只解析一句话，而是把“当前需求”和“可复用历史事实”合并成 B/C 节点能直接规划的状态。 其中 Intent Parser 处理当前输入，Memory 处理跨轮事实、偏好、关系和审计证据。

Intent Parser：理解这一轮用户说了什么

  • 输入：用户当前文本或 message list。
  • 输出：intent 与扁平化 constraints。
  • 典型字段：scene、time_window、people_count、budget、origin、hard_tags、soft_tags。
  • 生命周期：单轮为主，不负责长期记忆。
  • 维护重点：表达识别、标签标准化、缺槽位、当前输入准确性。

Memory：保存和召回跨轮可复用事实

  • 输入：当前 constraints、用户原文、已持久化 memory、可选 BaseStore。
  • 输出：投影后的 constraints、retrieved_memories、memory_updates、memory_trace。
  • 典型内容：孩子年龄、伴侣短期饮食状态、长期偏好、历史负反馈、value weights、实体关系。
  • 生命周期：跨轮，可 JSON 持久化，可同步 BaseStore。
  • 维护重点：当前输入优先、场景隔离、TTL、重复过滤、召回可审计。
问题 Intent Parser 的答案 Memory 的答案
用户当前要做什么？ 解析成 scene=family、today_afternoon、child_age=5、mom_diet=low_calorie。 不重新解析文本，只消费 parser 给出的 constraints。
哪些信息值得下轮复用？ 不负责判断长期价值。 写入 episode、孩子画像、伴侣低卡短期状态、graph relation。
历史能不能覆盖本轮输入？ 当前输入是解析来源。 不能覆盖。策略是 explicit_current_input_first，历史只补默认值和偏好。
朋友场景是否使用家庭记忆？ 只识别 scene=friends。 通过 scene-safe filter 跳过 child、wife、health 家庭专属记忆，并写入 skip reason。
为什么 planner 权重变化？ 给出场景、标签和显式约束。 激活 family_care、health、convenience 等 value memory，生成 value_weights 和 score_weights。

当前 Memory 实际会保存什么

类别保存内容来源作用
稳定用户画像 consumption_level、default_transport、长期偏好、规避项。 DEFAULT_MEMORY 或持久化 profile。 补默认交通、距离、排队容忍度和偏好；当前输入已有阈值时不覆盖。
同行人画像 孩子年龄与 kid_friendly、low_intensity；伴侣 dieting 与低卡轻食需求。 当前输入或历史 profile。 影响亲子/伴侣场景的硬约束和软偏好。
价值记忆 family_care、health、convenience、cost_sensitivity。 DEFAULT_VALUE_MEMORY 或 profile。 生成 value_weights 和 planner score_weights。
本轮 episode 用户原始输入、constraints 快照、场景标签、规避项、激活 value ids。 current_turn_memory_atoms。 短期上下文证据，默认 ttl_turns=6。
图关系 user -> travels_with -> child，wife -> prefers -> low_calorie。 MemoryAtom 的 relations。 支持 graph expansion，例如从 wife 扩展召回 low calorie 相关事实。
审计证据 retrieved、skipped、updates、semantic_sync。 build_memory_trace。 解释为什么召回、为什么跳过、写入是 upsert 还是 refresh。
一句话边界： Intent Parser 把当前话语变成结构化需求；Memory 把值得跨轮复用的事实、偏好、关系和审计证据存下来， 并在下一轮按场景安全地取出来影响规划。

主流程与数据流

Memory manager 是 A-stage 的第二个节点，输入是 intent parser 产出的 constraints 与用户原文， 输出会同时服务 B/C 节点、调试面板和测试审计。 

memory_manager_node(state):
  base_store = langgraph.config.get_store() or None
  memory = decay_short_term_items(load_memory(user_id, state.memory))
  constraints = apply_value_memory(state.constraints, memory)
  active_values = select_active_value_memory(constraints, memory)
  retrieved, retrieval_trace = retrieve_relevant_memories_with_trace(constraints, memory, semantic_store=base_store)
  turn_atoms = current_turn_memory_atoms(state, constraints, active_values)
  updated_memory, updates = apply_memory_updates(memory, turn_atoms)
  save_memory(updated_memory)              # JSON fallback when WF_MEMORY_STORE_PATH is set
  semantic_sync = persist_memory_to_store(base_store, updated_memory)
  return planner-facing + evidence-facing + audit-facing fields

Memory Atom 与 Store Schema

MemoryAtom 字段

字段含义
memory_id稳定唯一标识。固定事实如 current_spouse_diet 可重复 refresh。
kindepisode、companion、value、preference、feedback 等。
scopelong_term 或 short_term，影响排序和 TTL 处理。
summary/text检索和语义索引的主要文本。当前 text 默认等于 summary。
tags/entities/relationssparse 检索和 graph expansion 的核心结构。
ttl_turns短期记忆剩余轮数。episode 默认 6，伴侣低卡默认 4。
payload/raw_ref结构化事实和原始引用，trace 高相关时可展开。

JSON v2 用户记录

{
  "version": 2,
  "users": {
    "u001": {
      "user_id": "u001",
      "profile": {
        "stable_profile": {},
        "companion_profile": {},
        "preference_profile": {},
        "history_feedback": [],
        "derived_defaults": {},

      },
      "atoms": [],
      "graph": {
        "entities": {

        "relations": [

兼容策略： load_memory 会返回旧 planner 仍能消费的顶层 projection，同时保留 v2 的 profile、 atoms、graph。因此 B/C 节点不需要知道 v2 store 的细节。 未配置或未命中 JSON store 时会使用 deterministic default memory；一旦命中 v2 persisted user record， 记录里的空列表就是明确的用户状态，不会再被 DEFAULT_MEMORY 或 DEFAULT_VALUE_MEMORY 合并回默认偏好。

关键接口

接口输入输出说明
memory_manager_node(state) PlanState，至少需要 user_id、user_input、constraints。 constraints、memory、user_profile、retrieved_memories、memory_trace 等。 A-stage memory 唯一推荐入口。调用时会尝试从 LangGraph runtime 取 BaseStore。
get_graph(store=None) 可选 LangGraph BaseStore 实例。 可 invoke 的 graph。 传入 store 后，memory node 可执行 semantic search 和 store sync。
接口行为注意事项
load_memory(user_id, seed_memory=None)读取 JSON store 或默认 memory，并 normalize 为 planner 兼容结构。只有配置 WF_MEMORY_STORE_PATH 时才读 JSON 文件；命中 v2 persisted record 时不把默认 list 重新合并进去。
save_memory(memory)配置 JSON path 时将 memory 写为 v2 用户记录。未配置 path 时是 no-op。
JSONMemoryStore(path)提供 load、save，自动迁移 v1 payload。写入使用临时文件替换，适合本地单进程。
decay_short_term_items(memory)对短期 atom 和 companion profile 执行 turn-based TTL 衰减。由 memory_manager_node 在每轮开头调用。
接口行为返回
retrieve_relevant_memories_with_trace(...)融合 sparse、atoms、short-term、episodic、graph 和 semantic 候选。(retrieved, trace)，trace 含 sources、skipped、retrieved。
retrieve_relevant_memories(...)兼容旧调用，只返回 retrieved list。list[dict]。
expand_graph_memory_ids(...)从当前 constraints 推断实体，做最多 2 跳关系扩展。命中的 memory id 和路径。
semantic_search_memories(...)有 BaseStore 时按 constraints 拼 query 搜索。无 store 或 adapter 报错时返回空列表和 skip/error trace。
接口行为写入目标
current_turn_memory_atoms(...)把本轮输入生成 atom：episode、child profile、spouse diet。返回待写入 atom list。
apply_memory_updates(...)执行 upsert 或 duplicate refresh，并同步 projection。atoms、graph、episodic_memory、short_term_items、companion_profile。
build_memory_trace(...)合成 audit-facing payload。policy、retrieved、skipped、retrieval_sources、updates、semantic_sync。

PlanState 输出契约

planner-facing

  • constraints：投影后的规划约束，含 value weights、score weights、active value ids；当前输入里的排队阈值优先保留。
  • user_profile：紧凑画像，含 companion、偏好、规避项和 retrieved ids。
  • value_memory：本轮激活的 value memory item。

evidence-facing

  • memory：完整兼容 projection，含 v2 atoms 与 graph。
  • retrieved_memories：本轮安全可用证据。
  • memory_updates：写入或刷新操作，含 reason 和 ttl。

audit-facing

  • memory_trace.retrieved：分数、来源、graph hop、展开层级。
  • memory_trace.skipped：被 scene-safe filter 拦截的原因。
  • tool_results.memory_manager：调试快照。

使用方式

方式 A：无 LangGraph 依赖的本地 fallback

适合快速跑 demo 和测试。未安装 LangGraph 时 src/graph.py 自动使用 SequentialGraph。

PYTHONPATH=. python - <<'PY'
from src.graph import get_graph

graph = get_graph()
result = graph.invoke({
    "user_id": "u001",
    "user_input": "今天下午想和老婆孩子出去玩，孩子5岁，老婆最近在减肥，别太远",
})
print(result["constraints"]["active_value_ids"])
print(result["memory_trace"]["policy"])
PY

方式 B：JSON store 持久化

设置 WF_MEMORY_STORE_PATH 后，memory 会保存为 v2 JSON，并自动迁移旧 v1 payload。

export WF_MEMORY_STORE_PATH=/tmp/weekendflow-memory.json
PYTHONPATH=. python - <<'PY'
from src.nodes.intent_parser import parse_intent, constraints_from_intent

    "user_id": "u_json_user",
    "user_input": intent["raw_text"],
    "constraints": constraints_from_intent(intent),
    "short_term_memory": [],
})
print(result["memory_updates"])
PY

方式 C：LangGraph BaseStore

使用已创建的新环境 .venv-langgraph，可把 InMemoryStore 注入 graph。

source .venv-langgraph/bin/activate
PYTHONPATH=. python - <<'PY'

from src.graph import get_graph

store = InMemoryStore()
graph = get_graph(store=store)

    "user_id": "u_store_smoke",
    "user_input": "今天下午和老婆吃饭，老婆最近在减脂，吃得清爽一点",

print(result["memory_trace"]["semantic_sync"]["status"])
print(bool(store.search(("weekendflow", "memory", "u_store_smoke"), limit=3)))

排障与扩展点

现象优先检查处理方式
朋友场景出现孩子或伴侣偏好。 memory_trace.skipped、_scene_safety_reason、memory tags/entities。 确认 atom 是否带 child 或 wife tag/entity，并补 scene-safe 规则或测试。
重复输入导致 atom 数增长。 memory_updates[*].op 是否为 refresh，以及 _duplicate_signature。 把稳定事实写成固定 memory_id，或扩展 signature 字段。
短期伴侣饮食长期污染。 ttl_turns、decay_short_term_items、companion_profile.wife。 确认每轮都经过 memory_manager_node，不要绕过 TTL decay 后直接复用旧 memory。
BaseStore semantic search 没有命中。 memory_trace.retrieval_sources.semantic 和 semantic_sync。 无 store 是 skipped，adapter 报错是 error；两种情况都会自动回退 sparse。
JSON store 没有写文件。 WF_MEMORY_STORE_PATH 是否设置。 未设置时 save_memory 是 no-op，这是预期 fallback 行为。
已清空的偏好或伴侣需求又出现。 load_memory 是否命中 v2 persisted record，以及 profile 里的空列表是否被保留。 v2 persisted record 应按记录加载；空 avoid、wife.needs、value_profile 不应回填默认值。
